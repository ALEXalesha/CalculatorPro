# Тесты

Всего 491 автоматический тест плюс два e2e-смоука. Большая часть — property-based:
вместо «2 + 2 = 4» тест формулирует закон («сложение коммутативно», «undo всего
возвращает исходное состояние»), а генератор (FsCheck для C#, fast-check для JS)
проверяет его на 1000–5000 случайных входах. При падении генератор сжимает пример
до минимального и печатает его вместе с seed для воспроизведения.

## Calc Pro — `dotnet test calcpro-wpf\CalcPro.sln` (310)

**Грамматика** (`ParserPropertyTests`)
- Случайное дерево выражения → текст с минимальными скобками → парсер → то же дерево.
  Одно это свойство фиксирует всю таблицу приоритетов и ассоциативности.
- То же для полной расстановки скобок, лишних внешних скобок, пробелов в любом месте,
  символов × и ÷.
- Мусорный ввод даёт только `CalcParseException`. Вложенность в 100 000 скобок или
  минусов отклоняется, а не роняет процесс переполнением стека.

**Вычислитель** (`EvaluatorPropertyTests`, `EvaluatorExampleTests`)
- Законы: коммутативность и ассоциативность `+`, `*`; дистрибутивность; нейтральные
  элементы; `--a = a`; `(a·b)/b = a`; монотонность; `a^m·a^n = a^(m+n)`;
  `sqrt(a²) = |a|`; `n! = n·(n−1)!`; `sin² + cos² = 1` в обоих режимах углов;
  `asin(sin x) = x`; `ln(exp x) = x`; `log(10ⁿ) = n`.
- Результат всегда имеет не больше 12 знаков после запятой.
- Любое случайное дерево, в том числе с числами у границы `decimal`, даёт только
  `CalcEvalException`. Это ловит переполнения, которые раньше роняли приложение.
- Текст и дерево вычисляются одинаково; вычисление детерминировано.
- Таблица из ~80 известных ответов и математических ошибок.
- `DisplayFormat.Pretty` (× ÷ − на экране вместо ASCII) даёт текст, который токенизатор
  читает ровно так же, как исходный: те же токены на тех же позициях.

**Команды** (`CommandInvariantTests`, `CommandScenarioTests`)
- 3000 случайных последовательностей из 40 нажатий. После **каждого** нажатия проверяется:
  - дисплей — число или `Error`, `Error` только после `=`;
  - `=` в выражении ровно тогда, когда фаза `AfterEquals`;
  - скобки не отрицательны, после `=` сбалансированы;
  - фаза согласована с концом выражения (оператор, `(`, `)`, `%`);
  - главное: то, что вычислит `=`, всегда синтаксически корректно. Ошибка возможна
    только математическая, но не синтаксическая.
- Undo всех нажатий возвращает начальное состояние; каждый undo откатывает ровно одно
  нажатие; undo k + redo k — тождество.
- Набор `a op b =` совпадает с вычислителем; `(a) b` — это `a·b`; незакрытые скобки
  закрываются; `± ±` — тождество; `M+ x, M− x` не меняет память; история ≤ 50.
- ~70 сценариев «кнопка за кнопкой», каждый документирует одно поведение.

**Темы** (`ThemeFileTests`)
- Словари `Resources/Themes/*.xaml` читаются как XML: у всех пяти один и тот же набор
  ключей, текст на фоне не бледнее 7:1, на кнопках и на красных AC/C - 4.5:1.
- Во всей разметке, кроме самих тем, нет `StaticResource` к ключу темы.
- Любой текст из файла настроек даёт известную тему (свойство на FsCheck).
- Проверено мутациями: `StaticResource` в MainWindow, выброшенный ключ в «Светлой»,
  светлый текст на светлом фоне - каждый раз падает ровно нужная проверка.

## Calc Pro Glass — `npm test` (127) + `npm run test:e2e`

- Случайное дерево → текст (полные и минимальные скобки, пробелы, × ÷ −) → `evaluate`
  совпадает с прямым вычислением дерева в режимах DEG/RAD/GRAD (4000 деревьев).
- Мусор из токенов даёт только известные ошибки (`SYNTAX`, `DOMAIN`, …).
- `formatNumber` всегда выдаёт текст, который снова читается и сохраняет 12 значащих цифр.
- `decimalToFraction` восстанавливает любую `p/q` (q ≤ 1000) в несократимом виде.
- Автомат нажатий: 3000 случайных последовательностей по всем клавишам всех трёх режимов,
  переключениям, памяти и истории. Инварианты: нет `NaN`/`undefined`/`Infinity`, память
  конечна, после `=` дисплей равен `formatNumber(result)`, курсор дробей в границах.
  Это свойство нашло баг `EE` после `=` (экран `0E`, следующая цифра всё стирала): провал
  случался примерно раз на несколько прогонов, воспроизведён по seed 356620660.
- `a op b =` совпадает с парсером; процент в стиле Apple; дроби `p/q ∘ r/s` точны.
- Сохранение истории и памяти, устойчивость к повреждённому localStorage.
- **e2e:** Electron с тем же preload, CSP и sandbox; клики по кнопкам всех трёх режимов,
  проверка дисплея и истории, отсутствие ошибок в консоли, скриншот.

**Темы** (`test/themes.test.js`, одинаковый у Glass и iOS)
- У пяти тем в `themes.css` один набор переменных; `themes.css` и `theme.js` у двух
  Electron-калькуляторов совпадают байт в байт.
- Контраст: текст на фоне от 7:1, цифры и служебные клавиши от 4.5:1, белые символы на
  акценте от 2.5:1 (самое слабое - охра «Тёплой», 2.84:1). Эта проверка нашла контраст
  3.37:1 и 2.60:1 у AC, ± и % в «Стеклянной» и «Строгой».
- В стилях страницы нет прибитого белого стекла, белого текста и оранжевого Apple.
- Любое имя темы даёт известную тему, записанная возвращается при запуске, сломанное
  хранилище ничего не ломает (fast-check).
- **e2e:** меню из пяти тем, смена цветов, память о выборе через перезагрузку страницы,
  мусор в хранилище даёт «Стеклянную», Escape закрывает список и не стирает набранное.

## Calculator iOS 26 — `npm test` (54) + `npm run test:e2e`

- Регрессионный набор из старого `test-logic.js` плюс новые кейсы на исправленные баги.
- Цепочка операций сворачивается слева направо, как на iPhone (модель против движка, 2000 цепочек).
- `formatNumber ↔ parseDisplay` — обратимая пара; любое отформатированное число
  распознаётся как «последнее число» выражения.
- 3000 случайных последовательностей: нет `NaN`/`Infinity`, `Ошибка` стоит одна,
  показанный результат — число, память конечна, история ≤ 200.
- **e2e:** клики, разделитель тысяч, подсветка оператора, научная панель, 2nd, история,
  и проверка, что у страницы нет доступа к Node.js.

## Differential-проверка переноса

При выносе логики из HTML в модули старый inline-скрипт запускался в `vm` с заглушками
DOM параллельно с новым модулем на 3000 случайных последовательностях. Состояние
сравнивалось после каждого нажатия. Оба движка совпали полностью, и только после этого
были внесены исправления, описанные в CHANGELOG.
